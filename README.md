# 最爱老婆

两个人的生活手记。现阶段正在将前端 Demo 改为主机端持久化应用。

更新时间：2026-10-24。**本文件是项目唯一维护的说明文档**，统一记录功能现状、已确认需求、运行方法、存储设计和待办。后续功能开发同步更新这里，不再另建需求、交接或开发说明文档；第三方许可证按原文件保留。

## 项目目标与功能总览

网站名称为“最爱老婆”，记录夫妻两人的日常、旅行与重要经历。面向中国大陆访问，支持电脑和两部 iPhone，以浅粉底色、玫瑰粉按钮和日记卡片为当前视觉风格。最终内容仅供两人查看，当前出题模块已有账号权限，其余模块的全站私密认证仍待落实。

## 运行本地开发版

需要 Python 3.10 或更新版本。在 Windows 双击项目根目录的 `start.bat`，等待启动成功后打开：

http://127.0.0.1:8000/

第一次启动会创建 `.venv` 并安装 `requirements.txt`。如果安装中断，或者更新了依赖，可手动执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

保持服务进程运行。开发接口文档位于 http://127.0.0.1:8000/docs 。

### 同一局域网访问

双击根目录 `start-lan.bat`，终端会显示当前局域网网址，例如 `http://192.168.31.62:8000/`。其他设备连接同一路由器/Wi-Fi 后，使用这个地址。电脑必须保持开机、联网和服务运行；IP 可能随网络或 DHCP 分配改变，以启动时打印的地址为准。启动前先关闭占用 8000 端口的旧服务。

若其他设备无法连接，右键根目录 `enable-lan.bat`，选择“以管理员身份运行”，一次性添加 Windows 防火墙规则。规则只允许本地子网访问 TCP 8000，适用于当前 Windows 网络配置，不关闭防火墙。路由器访客网络/AP 隔离仍可能阻止设备互访。

此模式为局域网试用：互相出题模块已使用两人账号和后端会话控制，日记、故事、愿望、地图等原有模块仍保持当前局域网共享模式。全站私密认证尚待统一落实。普通局域网 HTTP 下可以在线写记录、在此设备暂存文字，但浏览器的 Service Worker 需要安全上下文，不能保证断网后重新加载页面；离线重开能力需后续 HTTPS。

没有配置路由器端口转发或公网隧道。

**8000 是主机数据库开发版；`couple-journal/start.bat` 的 8766 仍是旧前端 Demo。两者不迁移或合并数据。** 不会自动读取原 Demo 的 IndexedDB，也不会将示例日记插入主机数据库。

## 本阶段已实现

- 文字记录发布、编辑、补录日期；日期倒序列表及后端分页。
- 正文、标题与地点搜索；年份、月份、标签、故事筛选。
- 故事创建、收录记录、内部日期正序查看；删除故事保留记录。
- 自动草稿：主机数据库保存，设备上额外保留文字副本；联网时可重试保存。
- 页面外壳通过 Service Worker 缓存，成功在线访问后可断网重新打开，进入管理查看此设备草稿。首次离线访问无法安装外壳缓存；浏览器清理站点数据仍可能清除设备副本。
- 修改正文与标题时服务端保留历史，支持恢复文字版本。
- 记录和故事进入回收站、恢复；本阶段没有永久删除接口。
- 写事务、外键、索引、版本化初始化，以及编辑版本冲突检测。

记录标题选填，至少有正文或一个完整入库的附件即可发布，只有标题不能发布。发生日期默认今天，地点、标签和故事选填，允许补录过去日期。编辑不会按修改时间重新排序。

一条记录最多归入一个故事，故事内记录按发生日期从旧到新排列，仍出现在总时间线中。删除故事只解除归类，保留记录。故事选择框最多列出 100 个故事，年份和标签选项各最多 200 个；列表默认每页 20 条、接口最多每页 100 条，后续大量选项需要可搜索的分页选择器。

回收站恢复保留原发生日期、文字和其他实体状态；恢复记录时，原故事仍存在且有效才恢复归属。当前题目和答题记录没有删除接口。正文或标题修改会保留文字历史，恢复历史也会记录恢复前版本。

## 纪念日与进入网站提醒

侧栏或手机底部的“纪念日”提供新增、编辑、提醒开关、提前天数（0–30 天）、备注、倒计时及移入回收站/恢复。日期和配置保存在主机数据库，结构版本 2 的迁移保留原有文字资料。

每次进入网站时检查一次提醒：在配置的提前天数内及当天弹出，同一次访问不会因切换页面重复弹；正在编辑时延迟至编辑窗口关闭。按服务端北京时间计算，关闭浏览器时不推送。出题账号登录成功后也会检查，但同次访问已经展示过则不重复弹出。

用户已确认在一起 8/17、结婚 10/4、老婆生日 9/13、小昀生日 11/15 全部采用公历，进入网站时仅当天弹窗。结构版本 3 将这四个已存日期设为公历、提前天数 0；新增纪念日也默认仅当天提醒，仍可单独编辑。年份选填，生日填写出生年份后才计算年龄，其他纪念日填写起始年份后才计算周年。2/29 在实际闰日提醒，不转换为 2/28。

## 愿望清单

侧栏或手机底部的“愿望”入口支持新增、编辑、标记完成及撤销完成、全部/待完成/已完成筛选、搜索标题与备注、后端分页、查看整体完成进度。只需填写愿望标题；备注和目标日期选填。目标日期仅用于计划展示，不会自动触发通知。

愿望保存在同一主机数据库，电脑和手机访问同一个服务时共享。完成时间由服务端记录，编辑已完成愿望保留完成时间，撤销完成会清空该时间。删除先进入统一回收站，恢复时保留文字、目标日期和完成状态；没有永久删除接口。

点击卡片底部“标记已实现”或左侧爱心即可完成愿望，整张卡片变为浅绿色，并显示“已实现（点击撤销）”和实现日期；再次点击可撤销，恢复原来的粉色主题。状态保存在后台数据库，刷新后保留。

结构版本 4 新增愿望表及索引，升级保留日记、草稿、故事和纪念日。编辑、状态切换、删除和恢复均有事务与版本冲突检查。新增不插入示例或预设愿望。

## 中国地图足迹

侧栏或手机底部的“足迹”打开中国省级地图，点击地图标点，填写地点名称、可选到访日期和备注后保存。也可拖动地图，将地点放到中心十字处，再点“标定地图中心”。支持缩放、回到全国、在列表定位地点、编辑和重新选点；重新选点时保留已填写文字。

地图及交互库随项目保存，运行时通过本机服务提供，不需要地图 Key 或外部 CDN。底图为阿里云 DataV.GeoAtlas 提供的省级 GeoJSON，保留全部原始区域数据和署名；来源见本文“第三方资源与来源”。当前不提供街道导航、地址搜索、GPS 定位或日记关联。

结构版本 5 将地点坐标、地图来源、名称、到访日期、备注、版本及回收站状态保存在主机数据库。地点列表分页，地图按当前视野加载轻量标点（默认最多 500 个；超出时提示放大），不会把全部备注和记录一次性塞进地图。搜索同时筛选地图标记与地点列表。删除进入统一回收站，恢复后坐标和文字保留。

## 两人账号与互相出题

首次使用，在服务主机打开 http://127.0.0.1:8000/#quizzes ，点击右上“账号登录”或出题页“设置账号”，填写两个人各自的登录名、显示名字和密码。登录名为 3–32 位英文/数字/`_.-`，密码至少 8 位。只允许从服务主机的回环连接初始化一次，不预设密码，也没有开放注册第三个账号的入口。请直接在页面设置，勿把实际密码提交到源码或聊天。

随后两个人可分别在自己的浏览器/手机通过局域网网址登录。页面提供“待我回答”“我出的题”“答题记录”：

- 支持单选、多选，2–6 个选项，出题时选择正确答案，可填写解析。
- 出题人由后端登录会话确定，接收人自动为另一位账号；不能通过修改表单或请求指定自己来回答。
- 对方作答前接口不返回正确答案或解析；本人可回看自己出的题的答案。
- 每题保留一次正式提交。多选必须与正确选项集合完全一致才算正确；网络重试使用同一提交编号不会生成重复记录。
- 双方可回看原题、所有选项、对方选择、正确答案、对错和提交时间。发布后的题目固定，当前不提供修改或删除题目/答题记录的接口。
- 账号、密码哈希、会话及答题内容保存在主机数据库，重启服务后保留。会话有效期 7 天，退出即撤销；密码使用随机盐的 scrypt，数据库仅保存会话令牌哈希，浏览器使用 HttpOnly/SameSite Cookie。

本轮账号用于互相出题权限，未宣称其他模块已受账号保护。当前局域网 HTTP 未加密传输，正式私密部署仍需 HTTPS 与全站认证；忘记密码的恢复流程尚未实现。

## 照片、视频、音频与文档上传

打开“写一篇”，选择或拖入多个文件，允许文字与不同类型附件混合，也可以只发附件。支持调整附件顺序；每条记录最多 50 个附件。时间线可按图片、视频、音频、文档筛选，也可搜索文件名；相册按页汇集已发布且未删除记录的照片和视频，可回到所属记录，草稿内容不会进入相册。

每个文件单独显示真实传输进度，传完后等待服务端校验入库；最多同时传两个。失败只重试该文件，成功文件保留，只有所有选中附件完成后才能发布。离开页面后，未完成的文件需重新选择原文件，不提供字节级断点续传；已入库原件重新打开草稿后仍可使用。离线设备副本只保留文字与附件编号，不包含尚未上传的文件。

支持浏览器可解码的图片、视频和音频预览；视频/音频支持 HTTP Range 请求，便于拖动播放。PDF、Office、文本及未知格式按文档下载，不在页面执行 HTML/SVG 等主动内容。预览类型根据文件内容识别，不直接信任浏览器声明；不兼容格式仍可下载原件。当前直接读取原件预览，未生成缩略图或转码副本。

默认单文件上限 **1 GiB**，可在启动前设置正整数环境变量 `JOURNAL_MAX_UPLOAD_MB` 调整。接收前检查可用磁盘至少为声明文件大小的 1.15 倍再加 256 MiB；实际磁盘写入失败会返回错误，不能将未完成文件发布。视频“10 分钟以内”不等于一定小于文件上限。

上传保留浏览器实际交付文件的完整字节，逐文件记录大小与 SHA-256，原件不会被同名文件覆盖，也不按内容自动去重。HEIC/MOV 可以原样保存，但 iPhone 选择器可能只提供静态图或转换后的文件；**完整 Live Photo 配对和播放尚未实现**，需要两部真实 iPhone 验证。

从已发布记录移除附件，在保存记录后进入回收站；新上传文件从草稿移除也进入回收站。恢复时检查父记录或草稿、附件数量与版本，原件保留；删除整条记录只隐藏关联媒体，相册同步隐藏，恢复记录后可继续访问。

## 保存位置与边界

默认数据库固定在项目根目录的 `data/journal.sqlite3`，不会因为从其他工作目录启动而变成新库。可用 `JOURNAL_DB_PATH` 环境变量指定绝对路径。数据库和运行文件已被 `.gitignore` 排除，不上传 GitHub。

当前采用 Python + FastAPI/Uvicorn、原生 HTML/CSS/JavaScript 与 SQLite。主库保存文字、结构化数据及附件关联，连接开启外键、WAL 和 busy timeout；写操作使用事务，编辑通过 revision 检查并发冲突，旧版本返回 409。媒体原件分库存储，见下文。客户端不直接访问数据库文件，业务数据库、源码、Git 和开发快照目录均不作为静态资源提供。

主机上已经保存的业务数据由数据库持久化，设备上的浏览器存储只作文字草稿副本。Service Worker 仅缓存公开页面外壳、脚本、样式和底图，不缓存 API 私人内容。草稿冲突会保留设备副本，管理页可以另存新草稿；保存失败不清空正在编辑的文字。

默认 `start.bat` 仅监听本机回环地址；`start-lan.bat` 显式启用局域网监听并放行本机检测到的内网 IPv4 Host。两种模式使用同一主机数据库。出题模块已接入账号权限；全站认证、HTTPS 和真实 iPhone 验证仍待后续落实。

### 已确认的持久化与部署要求

- 所有正式业务数据都须保存在服务主机的本地数据库，包括媒体原件、未来完整 Live Photo 的全部组成资源、草稿、历史、附件关联和回收站状态。临时 URL、浏览器 Blob 或附件路径不能替代原件入库。
- 如果未来建议改成“数据库存索引，原件放文件系统”，须明确说明与原要求的差别、容量和备份权衡，并先取得用户同意。
- 不购买付费云服务器，先以用户电脑提供服务；主机睡眠、休眠、关机或断网时接受网站不可用。锁屏或只关闭屏幕可继续服务，合盖需实际配置不睡眠，当前没有替用户完成电源设置。
- 最终部署主机仍可调整，路径、端口和临时公网链接不作为正式环境硬编码依赖。当前未开放公网；将来试用期可讨论免费的临时公网入口，接受重启后链接改变，不承诺固定域名或生产可用性。
- 已知增长量约每年 1000 张照片、单段视频不超过 10 分钟。首批导入量、视频数量、单个文件字节数、磁盘容量及备份设备仍待确认；视频时长不能直接当作文件大小上限。
- 稳定 ID、明确关联、约束、索引、后端分页、事务一致性及有序数据库迁移属于持续要求。未来附件替换和异常中断不能导致原件提前清理、记录丢失或关联断裂。

### 数据库版本与媒体方案

| 结构版本 | 迁移内容 |
| --- | --- |
| 1 | 记录、标签、故事、草稿、文字历史 |
| 2 | 纪念日表及已知日期 |
| 3 | 四个日期确认为公历，默认仅当天提醒 |
| 4 | 愿望清单及完成状态 |
| 5 | 地图足迹及视野索引 |
| 6 | 两人账号、会话、登录失败计数、题目和答题记录 |
| 7 | 上传资源目录、状态、校验信息、附件顺序及回收站关联 |

`schema_migrations` 记录版本，升级只执行未应用迁移，保留旧数据；启动遇到更高版本会拒绝运行。后续不得通过删除数据库或清空重建代替迁移。

本轮采用主库加逐文件 SQLite 媒体分库：默认 `data/journal-media/objects/<编号前两位>/<编号>.sqlite3`。每份原件按 1 MiB 分块存为 BLOB，并保存编号、字节数、SHA-256 和识别类型；目录中的文件本身是数据库，不是原始图片或视频文件。设置 `JOURNAL_DB_PATH` 时，媒体目录随主库所在目录与主库名称派生。

接收时流式写入 `staging/` 中的临时 SQLite，原件完整提交后以不可覆盖方式放入 `objects/`，随后主库标记可用。发布记录只进行短暂的目录与关联事务，不在主库持有整个视频上传期间的写锁。异常重启会校验完整原件并补齐目录状态，未完整提交的临时上传可清理并重新选择；已确认原件不会自动清理。启动持有 `.service.lock` 进程锁，当前仅支持一个服务进程，不能启用多个 Uvicorn worker。

该方案面向当前两人使用、每年约 1000 张照片，将单库增长与写锁隔离到每个文件，并限制单文件大小、上传并发与分页查询。代价是数据库文件数量随附件增长；真实素材吞吐、手机兼容性、磁盘长期容量和完整备份耗时仍需实测，不能把临时数据库测试当作长期容量验收。

## 尚未实现

故事自定义封面、Live Photo 配对与播放、缩略图与自动转码、专用密钥永久删除、完整备份和恢复、全站账号权限。当前不能作为正式回忆的唯一保存方案。

不要将运行中的 `journal.sqlite3` 单文件复制视为完整备份；SQLite 的 WAL 可能仍含有已提交数据，而且原件位于 `journal-media` 数据库目录。完整备份需一致地保存主库及全部被引用的媒体数据库；开发快照仅供开发恢复，完整备份与独立目录恢复验证属于后续阶段。

### 媒体与相册的已确认要求

- 生活记录允许文字、多张图片、视频、音频混合；附件组可排序，首版不做任意图文穿插编辑器。地点首版手填，未来与地图关联需另行确认。
- 逐文件显示上传进度、失败可重试，成功文件保留；未传完的文件可重新选择，首版不承诺断点续传。
- 保留上传源文件，原件与缩略图/预览副本分开管理，不覆盖原件；记录资源归属、大小、校验信息和生命周期，避免误删仍被引用的资源。
- 相册自动汇集已发布记录的图片与视频，草稿附件不展示；可从素材回到所属记录。查找扩展到文件名与媒体类型。
- 浏览器支持的普通音视频直接预览，不兼容格式可提示下载原件，通用自动转码后续扩展。
- Live Photo 为核心类型，必须完整保留静态图和配对视频；只有照片或转成视频均不等于完整支持。须用两部实际 iPhone 验证浏览器能否取得完整资源，再决定导入/配对/播放方案；没有预先接受手动导出导入流程。
- 故事需要名称、封面、简介；记录与故事共享附件关联，不重复上传文件。当前自定义封面仍待实现。

### 永久删除与完整备份的已确认规则

- 普通删除无需密钥，先进入回收站；恢复无需密钥。未来移除或替换附件时，旧附件也应进入回收站，新文件不覆盖原件。
- 回收站内任何内容永久删除都必须由后端验证专用密钥，覆盖单项、批量和清空；不得添加绕过验证的自动清理或前端明文假校验。
- 实际密钥不写入源码、聊天或说明文档。设置、遗忘重置、验证会话及恢复冲突细节仍待明确；该规则保护网站操作，不能阻止有主机文件权限的人直接删除文件。
- 完整备份必须包含维持内容所需的媒体原件、记录、故事、标签、关联、历史等，并在独立干净目录恢复验证。草稿、回收站的备份范围、增量备份及恢复冲突策略需明确，不能无提示丢弃。
- 同盘开发快照只能辅助开发恢复，不能抵御整盘故障。后续有第二块硬盘或备份设备时再讨论定期自动备份。

### 后续开发与验收

接下来验证真实手机上传与播放，落实 iPhone Live Photo、永久删除密钥、完整备份恢复、全站认证与 HTTPS。现有文件大小、无内容去重和磁盘不足行为见上传说明；长期容量、备份周期、监控方式、性能指标和最终部署恢复方式逐步确认，不预先承诺未测数值。

正式验收需覆盖重启持久化、多设备同源读取、大规模分页检索、原件上传下载一致、异常中断回滚、记录/附件恢复、删除故事不丢记录、密钥保护全部永久删除入口、两部 iPhone 的 Live Photo 完整性，以及独立目录完整恢复。不能把浏览器存储 Demo、静态图预览、文字 JSON 导出或公开局域网试用当作全部验收通过。

愿望分类/优先级/分配、地图导航/路线/日记联动、其他题型、留言、点赞、共同编辑、那年今日、置顶故事均未确认为本轮功能；后续按明确需求扩展。
